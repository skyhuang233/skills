# 实施

实现用户所描述的工作。输入不固定：可以指向 `.scratch/<feature>/plan.md`，也可以是一段
口述描述。先确认本次要实现的工作范围；若输入是 ticket 引用，本仓库没有 tracker 机制，
直接向用户询问。

在动手写测试前，与用户确认本次要测的 seam。结果只留在对话中，不落文件。

调用 `/tdd`，按纵向切片推进：一个测试 → 一个最小实现 → 重复。

**每个红绿循环中，实现服从 `software-engineering-principle`。** 最容易违反的三类：

- 用默认值掩盖缺失字段，而不是尽早失败（第 2、3 条）；
- 把状态机拆成几个独立布尔，而不是让非法状态无法表示（第 1 条）；
- 为了让断言通过而加不必要的抽象（第 5、19 条）。

定期跑类型检查、跑单个测试文件，最后跑一次全量测试。

完成后调用 `/code-review` 审查这次工作。

把工作提交到当前分支。
