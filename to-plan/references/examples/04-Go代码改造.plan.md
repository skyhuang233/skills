### C2. 新建 `internal/platform/` 接口包

agent 与 MCP server 只依赖此接口，不直接 import 具体平台实现。**接口方法签名按 GitHub REST v3 规范设计**，作为 canonical model；各适配器只在偏离 GitHub 规范处做适配。

**`internal/platform/platform.go`** — 接口定义（实际实现，repo 在构造时绑定，方法不含 ctx/owner/repo）：

```go
package platform

type Platform interface {
    Name() string
    CurrentUser() (*User, error)
    GetIssue(number int) (*Issue, error)
    CloseIssue(number int) (*Issue, error)
    ListIssueComments(number int) ([]Comment, error)
    AddComment(number int, body string) (*Comment, error)
    AddLabel(number int, label string) error
    RemoveLabel(number int, label string) error
    ListLabels() ([]Label, error)
    CreateLabel(name, color, desc string) (*Label, error)
    ListOpenPullRequests(head, base string) ([]PullRequest, error)
    CreatePullRequest(head, base, title, body string) (*PullRequest, error)
    UpdatePullRequest(number int, title, body string) (*PullRequest, error)
    UpsertPullRequest(head, base, title, body string) (*PullRequest, bool, error)
    RepositoryURL(repository string) (string, error)
    IsNotFound(err error) bool
}
```

**`internal/platform/types.go`** — 平台无关 DTO（以 GitHub REST v3 wire 格式为 canonical）：

```go
type Issue struct {
    Number  int       `json:"number"`
    Title   string    `json:"title"`
    Body    string    `json:"body"`
    State   string    `json:"state"`
    Labels  []Label   `json:"labels"`
    User    User      `json:"user"`
    HTMLURL string    `json:"html_url"`
    Created time.Time `json:"created_at"`
    Updated time.Time `json:"updated_at"`
}

type Comment struct {
    ID      int64     `json:"id"`
    Body    string    `json:"body"`
    User    User      `json:"user"`
    Created time.Time `json:"created_at"`
    Updated time.Time `json:"updated_at"`
}

type PullRequest struct {
    Number  int    `json:"number"`
    Title   string `json:"title"`
    Body    string `json:"body"`
    State   string `json:"state"`
    HTMLURL string `json:"html_url"`
    Head    Branch `json:"head"`
    Base    Branch `json:"base"`
}
```

**`internal/platform/factory.go`** — 运行时选择（hostname 自动识别，默认 gitea）：

```go
func New(serverURL, baseURL, token, repo string) (Platform, error) {
    kind, err := detect(serverURL)
    // ...
    switch kind {
    case "github":  return newGitHub(baseURL, token, repo)
    case "forgejo": return newForgejo(baseURL, token, repo)
    default:        return newGitea(baseURL, token, repo)  // 默认 gitea（超集）
    }
}
```

适配器构造函数通过 `RegisterGitHub`/`RegisterGitea`/`RegisterForgejo` 注册（各适配器包 `init()` 调用），避免 import cycle。

### C3. 新建 `internal/platform/github/` 适配器（canonical）

GitHub REST v3 client，作为 canonical 实现。其他适配器以它为参照，仅覆盖偏离点。

| 维度 | GitHub REST v3（canonical） |
|------|---------------------------|
| Base URL | `https://api.github.com/repos/{owner}/{repo}/...`（或 `{GITHUB_SERVER_URL}/api/v3/...` for GHES） |
| Auth header | `Authorization: Bearer <pat>` |
| Labels | name-based `PUT /repos/{o}/{r}/issues/{n}/labels` |
| Issue attachments | 无原生附件——接口层不暴露 |
| PR head filter | `head` = `owner:branch` for forks |
| Projects | 不实现（本计划移除） |

需实现的方法（全部对应 `platform.Platform` 接口）：

- `GetIssue`：`GET /repos/{owner}/{repo}/issues/{number}`
- `ListIssueComments`：`GET /repos/{owner}/{repo}/issues/{number}/comments`
- `CreateIssueComment`：`POST /repos/{owner}/{repo}/issues/{number}/comments`
- `CloseIssue`：`PATCH /repos/{owner}/{repo}/issues/{number}` with `state: "closed"`
- `AddIssueLabels`：`POST /repos/{owner}/{repo}/issues/{number}/labels`
- `RemoveIssueLabel`：`DELETE /repos/{owner}/{repo}/issues/{number}/labels/{name}`
- `ReplaceIssueLabels`：`PUT /repos/{owner}/{repo}/issues/{number}/labels`
- `UpsertPullRequest`：`GET /repos/{owner}/{repo}/pulls?head={owner}:{branch}` 查找，不存在则 `POST /repos/{owner}/{repo}/pulls`
- `RepositoryURL`：`{GITHUB_SERVER_URL}/{owner}/{repo}.git`

新增 `github_test.go` conformance 测试（用 `httptest` mock）。

### C4. 新建 `internal/platform/gitea/` 适配器

Gitea API client，实现同一 `platform.Platform` 接口。Gitea API 与 GitHub REST v3 的差异点：

| 差异点 | GitHub（canonical） | Gitea 偏离 |
|--------|-------------------|------------|
| Base URL | `/repos/{owner}/{repo}/...` | `/api/v1/repos/{owner}/{repo}/...` |
| Auth header | `Authorization: Bearer <token>` | `Authorization: token <token>` |
| Labels | name-based `PUT` | ID-based：需先 `GET /labels` 查 ID，再 `POST /issues/{n}/labels` with label IDs |
| PR head filter | `head=owner:branch` | `head=branch`（不含 owner） |
| Issue attachments | 无 | 有 `assets` + `browser_download_url`（接口层不暴露，适配器忽略） |
| Projects | 不实现 | Gitea 有 repo-scoped board（本计划移除，不实现） |

实现策略：可共享一个 `baseClient`（HTTP transport + DTO 转换），gitea adapter 覆盖 URL prefix、auth header、label 操作与 PR head filter。新增 `gitea_test.go` conformance 测试。

### C5. `internal/platform/forgejo/` 适配器（薄包装 gitea）

Forgejo 是 Gitea 的 fork，API 几乎一致。`forgejo` 适配器 embed `gitea` 适配器，仅在 Forgejo 特有差异处 override：

```go
package forgejo

import "github.com/clawtroop/ai_native_dev/ai-native-act/internal/platform/gitea"

type Client struct {
    gitea.Client  // embed
}
```

从现有 `internal/forgejo/forgejo.go` 迁移：
- 保留 Gitea REST API（`/api/v1/`、`Authorization: token <pat>`）——与 gitea 共享。
- 保留 `GetIssue`、`ListIssueComments`、`CreateIssueComment`、`CloseIssue`、`AddIssueLabels`、`RemoveIssueLabel`、`ReplaceIssueLabels`、`UpsertPullRequest`、`RepositoryURL`。
- 删除 `ListProjects`、`CreateProject`、`ListProjectColumns`、`CreateProjectColumn`、`MoveIssueToColumn`（Project 看板移除）。
- 删除 attachment 下载逻辑（接口层不暴露）。
- Forgejo label 操作兼容 name-based（与 Gitea ID-based 不同），如确认有差异则 override `AddIssueLabels` / `ReplaceIssueLabels`。
- 将内部 Gitea DTO 转换为 `platform.Issue` / `platform.Comment` / `platform.PullRequest`。
- 保留现有测试，补充接口 conformance 测试。

### C6. Attachment 下载统一移除

`get_issue` MCP tool 的 attachment 下载逻辑在接口层移除——`platform.Issue` 不含 attachment 字段。Gitea/Forgejo 适配器不再下载附件；GitHub 无原生附件。agent 依赖 issue body 中的 inline markdown 图片。

### C7. [main.go](ai-native-act/cmd/ai-native-agent/main.go)

- 改读 GitHub 原生 env：
  - `FORGEJO_URL` → `GITHUB_SERVER_URL`
  - `FORGEJO_REPO` → `GITHUB_REPOSITORY`
  - `FORGEJO_TOKEN` → `GITHUB_TOKEN`
  - `AI_NATIVE_FORGEJO_TOKEN` → `AI_NATIVE_TOKEN`
  - `FORGEJO_MCP_COMMAND` → `AI_NATIVE_MCP_COMMAND`
- `GITHUB_EVENT_NAME`、`GITHUB_EVENT_PATH`、`GITHUB_RUN_NUMBER` 已被使用，保持不变。
- 平台识别无需额外 env：`platform.New()` 从 `GITHUB_SERVER_URL` hostname 自动推断。
- 知识库为可选：`AI_NATIVE_KNOWLEDGE_REPO` 未配置时 `prepareKnowledgeRepo` 直接返回 nil，agent 照常运行。
- 在 `AI_NATIVE_ISSUES_ROOT` 存在时，从 `GITHUB_SERVER_URL`、`GITHUB_REPOSITORY` 与 `ISSUE_NUMBER` 派生 `issueRoot`、`claudeHome` 和 `projectDir`；否则保留容器模式的 `/workspace`。
- 新增 `ensureIssueLayout`：创建 `claude/.claude` 和 `workspace`；从 `AI_NATIVE_AGENT_ROOT_SRC` 复制 settings、skills 和 templates 到 `claude/.claude/`，复制 `CLAUDE.md` 到 `workspace/`。不覆盖 session、`mcp.json`、`settings.local.json`、缓存和 execution summary。
- 把 `.mcp.json` / sandbox settings 的写入位置改为 `claude/.claude/mcp.json` 和 `claude/.claude/settings.local.json`。
- 新增协调仓与知识库的确定性 checkout：不存在则分别 clone 到 `workspace/${basename(GITHUB_REPOSITORY)}` 与 `workspace/${basename(AI_NATIVE_KNOWLEDGE_REPO)}`，已存在则 fetch 后按现有逻辑准备分支；启动时拒绝两者 basename 相同的配置。
- `configureGitCredentialHelper` 优先使用 `AI_NATIVE_TOKEN`，为空时回退 `GITHUB_TOKEN`；若 token 对知识库或目标仓无权限，保留 git 的明确认证失败，不静默降级。
- 启动 Claude 时设置 `HOME=claudeHome`、相应 XDG 目录、`CLAUDE_PROJECT_DIR=projectDir`，并将进程 CWD 设为 `projectDir`。
- 保持 `checkout_repository` 的现有实现；`REPOS_ROOT` 改为并保持在 `workspace/repos/`。
- Git identity 默认值：`ai-native-agent` / `ai-native-agent@example.local`。
- Bot/actor 过滤：移除 `forgejo-actions`、`gitea-actions`，保留 `github-actions` 与 `AI_Bot`。
- 所有 `internal/forgejo` import 改为 `internal/platform`（依赖接口）；`platform.New()` 在启动时选择具体适配器。
- `writeMCPConfig` 中 MCP server key 从 `"forgejo"` 改为 `"ai-native"`，默认 command 改为 `/usr/local/bin/ai-native-mcp`。
- `runSetup()` 删除 `ensureProject` 与输出 `AI_NATIVE_PROJECT_ID` 的逻辑，只初始化 labels。label 创建通过 `platform.Platform` 接口完成。

### C8. [session.go](ai-native-act/cmd/ai-native-agent/session.go)

- 彻底清除 TOS session 备份逻辑：删除 `objstore` import、`tosConfigFromEnv`、`sessionStore` struct 的 TOS 字段、`restore`/`persist` 的 TOS 分支。
- 简化为单一本地 session 查找路径：从 `${claudeHome}/.claude/projects/<escaped-projectDir>/` 找最新 JSONL，把其 ID 传给 `--resume`；找不到则返回空字符串（fresh session）。
- `main.go` 的 `newSessionStore` 不再分 TOS / 本地两条路径；session store 退化为「本地最新 JSONL 查找器」。
- `session_test.go` 删除 TOS 相关测试，保留并补充本地 session 查找的测试。
